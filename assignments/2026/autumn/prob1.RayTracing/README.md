# RayTracingNative

超算队纳新选拔题：优化一个基于《Ray Tracing in One Weekend》的 C++20 CPU 路径追踪渲染器。

基线采用单线程、逐物体线性求交、虚函数、`shared_ptr` 和递归弹射，没有加速结构。目标是在遵守场景、采样和计时规则的前提下提高性能。

## 编译与运行

需要支持 C++20 的编译器和 CMake 3.12 或更高版本。在项目根目录执行：

```bash
cmake -S . -B build -DRAYTRACING_WARNINGS_AS_ERRORS=ON
cmake --build build -j
./build/RayTracing
```

默认使用 Release 配置，编译选项跟随工具链，保留用户显式设置。GCC / Clang 启用 `-Wall -Wextra -Wpedantic`，MSVC 启用 `/W4`；`RAYTRACING_WARNINGS_AS_ERRORS` 控制是否将编译警告视为错误，默认关闭。

程序接受三个可选位置参数：

```text
./build/RayTracing [width] [samples_per_pixel] [output.ppm]
```

| 参数 | 含义 | 默认值 |
|---|---|---|
| `width` | 图像宽度，高度按 16:9 计算且至少为 1 | 1200 |
| `samples_per_pixel` | 每像素采样数 | 200 |
| `output.ppm` | 输出文件路径 | 当前目录下的 `out.ppm` |

默认评测配置为 1200×675、200 spp、最大弹射深度 50。宽度和采样数必须是 `int` 范围内的正整数；参数错误、文件打开或写入失败时，程序返回非零退出码。

快速查看渲染结果：

```bash
mkdir -p tmp logs
./build/RayTracing 320 20 tmp/preview.ppm > logs/render.log 2>&1
cat logs/render.log
```

输出采用纯文本 PPM（P3）格式，可用支持 PPM 的图像查看器打开，或安装 ImageMagick 后转换：

```bash
convert tmp/preview.ppm tmp/preview.png
```

场景包含天空渐变、灰色地面、约 480 个随机材质小球，以及三个分别使用玻璃、漫反射和金属材质的大球，支持抗锯齿与景深。

## 代码结构

| 路径 | 职责 |
|---|---|
| `src/main.cpp` | 命令行参数、固定场景、相机配置和计时 |
| `src/common.hpp` | 常量、固定随机数规则和角度转换 |
| `src/math/` | 向量、区间和颜色输出 |
| `src/geometry/` | 光线、命中记录、球体和线性求交遍历 |
| `src/material/` | 漫反射、金属和玻璃材质 |
| `src/render/` | 相机初始化、采样和路径追踪 |

源码直接包含所需头文件。`build/` 存放构建产物，`tmp/` 存放临时文件，`logs/` 存放日志，这些目录不属于发布源码。

## 优化规则

### 固定内容

- `src/main.cpp` 中的 `build_world()` 场景定义，以及命令行参数语义和默认值。
- `write_color()` 的输出规则：PPM P3、gamma 2 校正和 8 位量化。
- 每像素采样数、像素内均匀抖动、散焦盘采样、三种材质的散射分布、天空渐变和最大弹射深度 50。
- 下述随机数规则和计时范围。

违反固定内容的提交不参与性能评分。

### 随机数规则

场景和像素使用独立的随机状态，算法固定为 `std::mt19937` 和 `std::uniform_real_distribution<double>(0.0, 1.0)`。

场景通过 `begin_scene_random()` 使用种子 `42u`。像素编号为 `j * image_width + i`，通过 `begin_pixel_random()` 使用 `std::seed_seq{42u, 编号低32位, 编号高32位}` 初始化。每个像素仅初始化一次，随后依次计算该像素的全部样本和弹射。

禁止修改 RNG 算法、种子及派生方式、像素内的随机数消耗顺序，禁止跳过随机调用或为每个样本重新设置种子。状态按线程隔离，允许改变像素调度顺序；线程数与调度不得改变像素的随机序列。场景与参考图由统一的编译器及标准库生成。

### 允许优化

- 求交算法、加速结构（如 BVH）、数据布局（如 SoA）、虚函数和所有权管理。
- 多线程、像素调度和 SIMD，保持规定的采样序列与数学语义。
- CMake 配置与编译选项，以及优化所需的新文件。

## 计时与评测

程序向 stderr 输出逐行进度，向 stdout 输出初始化耗时和最终的 `Render time: X.XXX s`。

`Render time` 是用于评分的渲染总墙钟时间，使用 `std::chrono::steady_clock`，从初始化完成后、进入 `camera::render()` 前开始，到 PPM 文件关闭并完成流缓冲写出后结束。

| 计入渲染总时间 | 单独报告，不计入渲染总时间 |
|---|---|
| 逐像素 RNG 初始化、采样、求交、散射和颜色处理 | 场景生成和 BVH 等加速结构构建 |
| 渲染任务调度、计算完成后的线程等待和进度输出 | 相机计算、缓冲区分配和工作线程预启动 |
| PPM 写入及文件关闭 | 命令行解析和文件打开（无需单独计时） |

计时前不得预生成像素随机序列、追踪光线、计算像素颜色或加载缓存图像。所有渲染任务必须在计时结束前完成，图片必须完整写出；不要求磁盘 `fsync`。新增的初始化阶段应单独报告耗时。

评测使用默认配置，统一机器、编译器与标准库版本、可用 CPU 核及线程资源、输出磁盘和日志重定向方式。不同实现顺序运行，避免资源竞争。

一次完整预热后，正式运行 3 次取 `Render time` 中位数。每次使用新进程，生成完整 PPM 并返回 0。加速比为同条件下基线中位数除以选手中位数；计时边界和打印代码由队内审核。

参考图和正式性能基线需要在评测机生成，PSNR 计算方式与阈值待测试后确定。参考图必须来自当前版本；旧版使用不同的随机序列和编译配置，其参考图与耗时不作为当前评分依据。

### 基线实测

当前版本使用默认配置、单线程运行 `time ./build/RayTracing`，一次完整运行的结果如下（由队长提供）：

| 项目 | 实测值 |
|---|---|
| 渲染总时间 `Render time` | 1223.179 s（约 20 分 23 秒） |
| 场景初始化 | 0.000106 s |
| 相机初始化 | 0.000025 s |
| shell 总耗时 | 20:23.18 |
| 用户态 / 内核态 CPU 时间 | 1222.97 s / 0.16 s |
| CPU 使用率 | 99% |

程序计时与 shell 总耗时一致，初始化开销很小。这是单次实测记录；正式评分仍使用统一评测环境下三次运行的中位数。

## 优化方向

可以从多线程和 BVH 入手，再考虑 SIMD、内存布局及去虚函数化。默认 Release 已采用工具链优化选项，调整编译选项时应检查实际编译命令。多线程渲染必须保留每像素的固定随机序列。
