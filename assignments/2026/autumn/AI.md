# 超算队AI方向选拔赛题：单卡扩散语言模型推理与微调优化

## 一、赛题背景与目标

扩散语言模型通过多轮去噪生成文本，为语言模型的并行推理提供了新的实现路径。本题采用SDAR块扩散语言模型：按顺序生成文本块，在块内迭代预测多个token。其性能受到去噪轮数、缓存复用、算子实现和显存管理等因素的共同影响。[SDAR项目](https://github.com/JetAstra/SDAR)

参赛者需在单张24GB GPU（建议不是绝对）上完成**推理优化**与**高效微调**两项任务中的一项，围绕指定模型和数据集分析性能瓶颈，设计优化方案，并通过实验说明速度、显存与模型质量之间的关系。我们鼓励深度探索一项任务。足够深度探索一项任务会比两项任务都浅探索的分数更高。

统一使用以下版本：

- 模型revision：`56bca3c8d927410589a86e7996ee281b6764fa37`。

模型为稠密结构，实际参数量4,411,424,256，包含36层Transformer，hidden size为2560，intermediate size为9728，32个Query heads、8个KV heads，head dimension为128，词表大小151936。模型采用大小为4的文本块。[模型配置](https://github.com/JetAstra/SDAR/blob/4c2749ba103448f45520e8411533710a1e66574d/training/model/SDAR-4B-Chat/config.json)

### 2. 数据划分

GSM8K包含7473条训练样本和1319条测试样本，每条样本包括数学问题、解题过程与最终答案。[数据说明](https://github.com/openai/grade-school-math)

- **训练集**：从官方train中选取4000条样本。
- **验证集**：从官方train中另取256条样本，用于选择训练与推理参数。
- **测试集**：使用官方test全部1319条样本，进行最终性能与质量评测。

训练与验证划分采用固定流程：使用Python 3.10的`random.Random(42).sample(range(7473), 7473)`生成索引顺序，按下述聊天模板编码完整问答，保留长度不超过512 tokens的样本；前4000条作为训练集，接下来的256条作为验证集。提交实际样本索引文件。测试集保持完整，按`random.Random(42).sample(range(1319), 1319)`确定处理顺序。

user消息为原始问题加以下后缀，再使用指定模型自带的chat template：

```text
Please reason step by step, and put your final answer within \boxed{}.
```

训练时保留原始解题过程，将答案末尾的`#### 数字`替换为`\boxed{数字}`：assistant内容为`解题过程.strip() + "\n\\boxed{" + 数值.strip() + "}"`。长度过滤采用`apply_chat_template([user消息, assistant消息], tokenize=True, add_generation_prompt=False)`的完整结果，包含模板生成的特殊token，过滤发生在padding之前；其余模板参数保留模型默认值。prompt部分不参与损失计算，样本边界与块掩码按SDAR训练实现处理。验证集用于调参，测试集用于最终报告。

## 四、任务一：推理优化

### 1. 任务内容

使用指定原始模型完成GSM8K测试集推理（至少取前64个样本进行推理，可见附录），在保持回答准确率的前提下缩短端到端耗时。默认逐条推理，`batch_size=1`，每条回答最多生成512 tokens。

参赛者可调整计算精度、去噪策略、缓存机制和算子实现。提示模板、测试样本及最大输出长度保持一致；使用量化模型时，从指定权重转换。推理任务使用未微调模型，微调后的模型在任务二中单独评测。

批处理与动态调度可作为拓展实验，另报batch size、吞吐和显存，和逐条推理结果分别展示。

### 2. 质量评价

采用数值答案准确率（Exact Match）：优先读取最后一个非嵌套`\boxed{...}`中的数值；无该标记时，读取文本中的最后一个数值。去除千分位逗号、货币符号和句末句号后进行十进制规范化，与标准答案比较，无法解析记为错误。具体提取规则采用随题脚本的`numeric()`函数。

优化后的测试准确率相对附录所列原始实现，请权衡加速比的提升与正确率在同一完整测试集上的下降！报告同时提供逐题输出和准确率变化。

### 3. 评测指标

- **端到端总耗时**：完成全部测试样本的进程wall-clock时间。
- **加速比**：同机原始实现总耗时除以优化后总耗时。
- **端到端吞吐**：完成样本数除以总耗时；另报有效输出tokens/s。
- **资源与质量**：峰值显存、准确率、有效输出长度、模型前向调用次数。

加速比为2.0×表示总耗时减半、同工作量吞吐提高100%。有效输出token按首个停止token截断后统计，不包含prompt和padding。建议重复运行3次，报告各次结果及总耗时中位数。

## 五、任务二：高效微调

### 1. 任务内容

在指定4000条训练样本上完成**2个epoch**的微调，采用SDAR的扩散训练目标。允许使用LoRA、QLoRA等参数高效方法，优化器、学习率、micro-batch size和梯度累积步数自行选择，序列长度上限为512 tokens。

参赛者应分析训练中的显存与计算开销，完成至少一项有实验支撑的优化探索，例如比较不同LoRA rank、梯度检查点配置或算子实现。两组实验可使用相同训练预算的短程对照，最终方案须完成规定训练量。

### 2. 评测指标

本任务不设统一训练对照实现，不要求全参数微调或提交训练加速比。可报告：

- 含权重加载和最终保存的训练总耗时。
- 训练吞吐：样本呈现次数/秒、非padding训练tokens/秒，并注明计时区间。
- 峰值显存、可训练参数量及其占总参数的比例。
- loss曲线、实际优化器更新步数及关键超参数。
- 微调前后在完整测试集上的准确率与变化。

微调前后的质量评测使用同一提示、采样与答案提取配置。模型效果、资源消耗和实验分析共同计入评分。

### 3. 模型交付

提交最终adapter或完整微调权重、配置文件及加载脚本。使用adapter时注明依赖的原始模型版本；提供从指定原始模型到最终结果的训练命令。

## 六、参考优化方向

以下方法供选题参考，可选择其中若干项组合实现。

### 1. 推理方向

| 方法           | 可探索内容                                                   |
| -------------- | ------------------------------------------------------------ |
| 混合精度与量化 | 调整矩阵乘法、归一化等运算精度，探索低比特权重及其反量化开销，评估速度与准确率变化。 |
| 算子改造与编译 | 使用`torch.compile`或Triton改造RMSNorm、MLP及采样相关算子，减少kernel launch和中间张量读写。[PyTorch编译文档](https://docs.pytorch.org/docs/stable/torch.compiler.html) |
| 缓存与并行解码 | 参考Fast-dLLM的KV缓存和置信度并行解码，调整缓存复用范围、解掩码数量与去噪轮数。[Fast-dLLM](https://github.com/NVlabs/Fast-dLLM) |
| 执行与调度优化 | 分析CPU调度、数据搬运和GPU空闲时间；尝试CUDA Graph或SDAR的JetEngine、LMDeploy实现，批处理作为拓展。[SDAR推理入口](https://github.com/JetAstra/SDAR#-usage) |

Fast-dLLM作为加速方法与代码参考，重点考察其缓存和并行解码思想在SDAR块扩散流程中的适配；可移植相关实现，也可基于SDAR已有缓存进一步优化。

### 2. 微调方向

| 方法               | 可探索内容                                                   |
| ------------------ | ------------------------------------------------------------ |
| LoRA               | 选择注入层、rank与缩放系数，分析可训练参数量、训练速度和效果。[PEFT文档](https://huggingface.co/docs/peft/developer_guides/lora) |
| QLoRA              | 量化冻结基座并训练低秩参数，评估显存节省、反量化开销与数值稳定性。[QLoRA论文](https://arxiv.org/abs/2305.14314) |
| 梯度检查点（GC）   | 用重计算减少激活存储，比较不同检查点粒度及其对可用batch size的影响。[PyTorch文档](https://docs.pytorch.org/docs/stable/checkpoint.html) |
| 训练算子与数据组织 | 探索混合精度、融合损失、长度分桶和序列packing，减少临时张量与padding计算。[SDAR训练代码](https://github.com/JetAstra/SDAR/tree/4c2749ba103448f45520e8411533710a1e66574d/training) |
